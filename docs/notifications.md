# 通知（2026年10月21日）

## 利用方法

ログイン後、右上のベルから開く。赤い数字は未読件数。日時・内容・差出人を表示し、タップで既読にして注文や相談へ移動する。30件ずつ読み進められる。

対象：購入希望／仮押さえ、承認による販売確定、数量・送料の変更提案と同意、見送り、取消、期限切れ、注文内のメッセージ、出品への相談・返信、「探しています」に応えた出品。

通知画面の「通知を許可する」で、この端末へのWeb Pushを設定する。自動で許可を要求しない。「この端末の通知をオフにする」で停止できる。「テスト通知を送る」で実機受信を確認する。ログアウト時にもこの端末の購読を解除する。

iPhone：Safariの共有→ホーム画面に追加→追加したLocAIを開く→通知のベル→通知を許可する。iOS/iPadOS 16.4以降。Android等は対応ブラウザで許可する。端末設定、集中モード、電池・通信状況により到着が遅れる場合がある。ロック画面には到着だけを表示し、私信・相手の名前・注文内容を複製しない。

## 保存・配信

- 通知と取引変更は同一トランザクション。出来事と宛先の組み合わせを一意にして再送の重複を防ぐ。
- 通知・既読・端末のAPIはセッションと所有者を確認。変更は同一OriginのPOST/DELETEだけ。Push送信先は既知の配信事業者のHTTPSホストに限定する。
- メッセージ本文は通知へコピーしない。通知はAIへ渡さない。
- 取引を確定した応答の後、NextのafterでPushを配信。通知・端末ごとの配信記録と2分の処理権で同時配信を抑制し、失敗は最大5回まで再試行する。404/410の端末購読は削除する。外部PushサービスとDBの間は厳密なexactly-onceではなく、応答喪失時に同じタグで再送する可能性がある。
- 許可前の過去通知はPushで送らない。既読済みの通知も新たに配信しない。
- 期限切れ：利用中は30秒ごと、次に開いたとき、およびVercel Cronで1日1回（日本時間0時台）に確認。Hobbyでは日次・時刻に幅があるため、閉じている間の期限切れ通知は最大約1日遅れる場合がある。在庫計算そのものは従来どおり期限を過ぎた瞬間から仮押さえを除外する。
- 日次確認は100出品、1回のキュー作成50通知・送信15端末まで。小規模デモ用。大規模な運用や即時の期限通知には定期処理頻度・配信ワーカーの拡張が必要。

## 設定

Vercel Production：WEB_PUSH_PUBLIC_KEY、WEB_PUSH_PRIVATE_KEY、CRON_SECRET。専用鍵は作成済み。値はGitやログに出さない。端末購読と結び付くため、VAPID鍵を理由なく作り直さない。Previewには本番の鍵・本番DBを接続しない。

7番目のPrisma migrationはnotification、push_subscription、push_deliveryの追加だけ。既存の出品・注文・アカウントを削除しない。

## 確認

- 単体：Push送信先の許可／拒否。
- DB：当事者だけ、既読の所有者、二重送信、全取引イベント、期限境界と同時実行、メッセージ・相談の再送、注文と通知のロールバック、ページ送り、出品による返答、Push送信の排他と無効端末の削除。
- 画面：相談→ベル→既読→返信、320/390/1280px、認証・CSRF、実ブラウザのService Worker登録、模擬イベントによる受信ハンドラと通知クリック処理、許可ボタンから端末登録・停止の所有者確認。
- ブラウザ自動確認ではPushサービスの接続を代役にしている。実際のiPhone/Androidへの到着は、本人が通知を許可した端末で「テスト通知を送る」を押して確認する必要がある。
